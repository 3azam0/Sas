# Fodo v0.1.0 — local restaurant inventory foundation

Initial local prototype release. Hosted production remains pending.

Arabic RTL inventory screens support seeded organizations and locations, material receiving, waste, stock quantity/value, FIFO costing, movement history, and offline capture with exactly-once reconnect posting. Rejected operations can be reviewed, retried, corrected or cancelled. Recovery archives preserve queued work with scope/payload validation and duplicate handling. The local launcher uses a stable origin and database ownership checks; verified backups can restore into a separate destination.

GitHub workflow files define type checking, unit/integration tests, production build, offline/recovery/launcher browser scenarios, and full-history secret scanning. Version tags prepare a validated source manifest and draft release. Repository protection and environment registration depend on successful owner-session setup and remote verification. This version supports a local prototype; hosted production authentication, cloud schema/sync, complete purchasing, transfers, recipes and cost-control workflows remain pending.

Validation on 9 October 2026: typecheck, 27 unit/integration tests, production build, and nine browser/process scenarios passed locally. Workflow syntax and committed-history secret scanning passed. Remote Actions results must pass before the release is prepared.

This workflow change adds no database migrations or changes to posted inventory, command versions or recovery envelopes. Preserve local database backups and pending browser operations before changing versions. Keep the same local origin during an upgrade. Return to a compatible prior build only after confirming it understands the current database/command formats; a source revert does not reverse posted stock movements. Future schema changes require explicit migration and older-client compatibility validation.
